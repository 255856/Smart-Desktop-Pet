## 详情

### P1 MiniMax-M3 完全不调工具 ✅ `4f4c2aa`

**症状**：主人说「查一下广州天气，提醒我明天带伞」，6 轮没调成任何工具，回「刚刚那个操作没能完成」。

**根因**：MiniMax 官方文档 `tool_choice` 合法值只有 `"auto"` / `"none"` / **指定具体工具**，`"required"` 不在其中。服务端不报错直接吞掉——这让它看起来像「模型不听话」。实测更糟：**发了反而更差**。

| 策略 | 命中 |
|---|---|
| `tool_choice="required"`（原第 1 轮） | **1/12** |
| `tool_choice` 指定具体工具（官方支持写法） | 1/12 |
| 不带 `tool_choice` | 4/12 |
| 不带 + 干净强制提示 | **9/12** |

**修复**
- 出厂预置黑名单 `{"minimax-m3"}` 直接不发 `tool_choice`；**必须做模型名大小写归一化**（config 是 `MiniMax-M3`，表里是小写，不归一化永远命中不了）
- 运行期学到的名单落盘 `data/tool_choice_unsupported.json`
- `force_tool_use` 从 `turn == 0` 改为**贯穿整个重试阶段**（原来第 1 轮失败后 2~6 轮完全无强制）
- 删掉 AgentLoop 自拼的 `[系统提醒]` 伪 user 消息（实测 5/12，与主提示叠加更差 4/12）

**验证**：端到端真实 API 15 次成功 14 次（修复前 6 轮全挂 0 次）。埋点确认 payload 中 `tool_choice` 恒为 `None`。

### P2 get_weather 每次 400 ✅ `4f4c2aa`

`humidity_2m` → `relative_humidity_2m`（请求参数与结果取值同步改）。此前天气工具**从未成功过**，错误被转成「工具出错了」所以没人发现。

### P3 播报与实况矛盾 ✅ `24692ba`

**不是「没带日期」**，日期一直带着。是两个接口对同一天打架：

```
current : time=2026-10-14T15:15  weather_code=0   → 晴
daily[0]: date=2026-10-14        weather_code=51  → 毛毛雨 31%
```

`daily` 是**全天 24h 汇总**，凌晨下过雨就把整天标成雨，哪怕此刻大太阳。

**修复**：当天行不再报天气现象与降水概率，只保留高低温 + 注明「以『当前』为准」。未来几天不受影响。

### P4 查天气不查够天数 ✅ `24692ba`

工具描述与 `days` 参数写死：问「明天/后天/周末」必须传够（明天 2、后天 3）。

### P5 天气白名单缺 get_weather ✅ `d9f5597`

| 说法 | 命中意图 | 白名单有 `get_weather`？ |
|---|---|---|
| 查一下天气 | `query` | ❌ |
| 查一下广州天气 | `web_search`（`query` 正则被城市名打断） | ❌ |

模型拿不到内置工具 → `web_search`+`fetch_url_text` 爬中央气象台 → **58.9s / 4 请求**，回复还漏爬取独白。

**修复**：新增独立 `get_weather` 意图（容忍夹城市名）；给 `query`/`web_search`/`open_app` 三个白名单补 `get_weather`；`get_weather` 白名单内保留 `web_search` 供「查火星天气」退回联网。

### P6 否定句被当动作 ⚠️ `d9f5597`

「不要提醒我任何东西」命中「提醒我」→ 查提醒列表 → 回「已经帮主人搞定啦~」。主人说**别做**，它做完还报喜。

**已修**：命中位置**之前**窗口内出现否定词（不要/别/不用/不需要/无需/没必要/禁止/甭/勿/取消）即跳过。方向要分清：否定词在动作词**之后**不算数——「提醒我别忘了带伞」仍应判 `add_reminder`。

**未修**：`detect_action_intent` 返回 `None` 只让 `force_first_turn=False`，工具集照样全量下发，模型仍可能主动调。彻底修要「首个分句被否定 → 整轮撤工具」，但「不要打开那个软件，顺便查下天气」会误伤，需先定混合句规则。

### P7 HTTP 529 空气泡 ✅ `d9f5597`

MiniMax 集群繁忙返回 `HTTP 529 overloaded_error`，旧实现直接抛 → 主人等半天收到空气泡。

**修复**：抽出 `_stream_once()`，外层加重试。瞬时码 `408/409/425/429/500/502/503/504/529` 最多 3 次（1.5s/3s 线性退避）；`4xx` 不重试；重试只包住「还没吐字节」的阶段，不会重放已 yield 内容。

### P8 全路径无产出空气泡 ✅ `e294495`

「记一下我讨厌香菜，然后提醒我今晚吃饭」跑 6 轮 9 次工具调用，最后一条文字都没产出（间歇性）。

原有两条兜底各有前提（要 `executed_tools` 非空 / 要 `over_sanitized`），都不成立就不发声。

**修复**：加**无条件**兜底。最窄的缝（既没调工具也没吐内容）也必须给一句诚实的「我没说完」。

---

### P9 多步任务只做一半 ✅ `d9f5597`

「查广州天气 + 明天带伞提醒」→ 模型调完 `get_weather` 就收尾，提醒那半被吞。

**判据用数量不用工具名**：曾试「意图对应的工具调了没有」，**被实测否决回退**——意图名 ≠ 实际工具名（「搜十月新番并打开B站」意图判 `open_app`，实际调 `web_search`+`open_website`，按名字比成「一件都没做」，白刷 3 轮）。

```python
count_request_actions(text)   # 纯语言分句计数
「查一下广州天气，提醒我明天带伞」 → 2
「帮我搜一下十月新番，并打开B站」 → 2
「今天天气怎么样」               → 0（无动作动词）
```

要求 N 件、实做 M<M 时给**一次**纠正（硬限 1 次）。

**验证**：L3 层 62% → **81%**，剩余 3 条全是压测台拦截 `open_website` 的假失败（模型如实报告「被压测拦截」「地图连试好几个打不开」，正是期望行为）。

### P10 单请求延迟 ❌ 根因不可解

| 用例 | 耗时 | 单请求拆解 |
|---|---|---|
| 超长输入 | 100.0s→29.4s | — |
| 查一下广州天气 | 47.1s | `[41.9, 3.2]` |
| 搜一下最近的AI新闻 | 60.4s | `[43.4, 1.9, 5.6]` |
| 不要提醒我任何东西 | 96.3s | `[47.8, 48.4]` |

慢在**单个请求**而非重试循环 → MiniMax-M3 推理延迟，代码层改不动。

**体验侧已覆盖**：`chat_window._typing_dots_html()` 的三点动画从占位气泡插入那刻就在跑，整个等待期都有反馈。**不需要**再造「还在想」提示，那是重复投资。

剩余可做：首 token 超时阈值 + 降级非推理模式；`extra_body={"reasoning_split": True}` 缩短首字延迟。

### P11 内部核对话术泄漏 ✅ `ea9a184`

实测泄漏样本：

```
要查火星天气。1. 工具都成功执行了
2. 主人要求：查火星天气 - 我已经搜到了相关数据
3. 数据来源确认：

让我查广州天气。从最后一次抓取中央气象台的页面拿到了完整的预报数据：…

1. get_weather（成功）：广州 晴 33度
请给主人最终答复
```

`_strip_meta_by_sentence` 是**逐句**判污染，盖不住**行级**形态。

**修复**：`_strip_internal_checklist()` 删「行首序号 + 内部过程词」「`工具名（成功）`」「无序号爬取叙述」三类行/句。

**关键：句级词表必须收窄**。行级宽表含「我查」「我搜」，而**「我查到的天气是晴」是对主人能说的话**，按宽表删会清空正文——比泄漏更糟。句级只收「抓取/爬取页面」「调用 schema」「给主人最终答复」。

### P12 web_search 无降级后端 ✅⚠️ `ea9a184`

`requirements.txt` 里 `ddgs>=9.0.0` 被注释掉。Tavily 一失败就整个不可用，且 Tavily 的错误被吃掉后才轮到这里，主人只看到「搜索失败」。已取消注释并装进 `.local-packages`。

**⚠️ 装了不等于能用**：实测 `ddgs` 打的是 `https://www.google.com/wml/search`，中文网**必超时**。真要兜底得换国内可达的免 key 源，或在设置页暴露后端开关并如实告知可用性。

---

### P13 同一失败工具反复重试 ✅ `ea9a184`

模型对打不开的网页连调 6 次 `open_website`，每次只换参数。

**修复**：按工具名计失败（跨轮次），连续 `_MAX_SAME_TOOL_FAIL=2` 次后本轮不再提供，并明确告知模型「换条路或如实告知主人做不到」。成功清零；只数「工具自己说没成」，主人取消/确认超时不算。

## 排查陷阱（会浪费时间的坑）

1. **意图名 ≠ 实际会用的工具名**。任何靠名字对齐意图与行为的方案，先找反例。
2. **`tool_choice` 服务端不报错 ≠ 参数生效**。国产模型会静默吞掉未支持的取值。
3. **Tavily key 在 `config.yaml` 的 `brain:` 段**，不在 `llm:` 段。读错段位会误判成「应用没传 key」——应用是对的。
4. **清洗器比泄漏更危险**。词表放宽会把正常回复清成空气泡。新增删除规则必须配「不许误删」的反向用例。
5. **压测台自己的 bug 会伪装成被测代码的 bug**。本轮曾把「只读工具被调用」误报成 `DANGER_EXECUTED`，而实际那两条都是正确行为。下结论前逐条回看原始输出。
6. **期望写错比实现写错更隐蔽**。首轮 6 条失败里 4 条是语料期望写反了。
